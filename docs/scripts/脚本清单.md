### 1.1 migrate_v0_to_v1.py - Schema 迁移

**功能**: 将 LanceDB 中的 Schema 元数据升级到 v1 增强版本，支持从数据库导入、统计信息提取、关系分析等功能。

**使用方式**:
```bash
python scripts/migrate_v0_to_v1.py --config=conf/agent.yml [选项]
```

**核心参数**:
| 参数 | 说明 | 默认值 |
|------|------|--------|
| `--config` | 配置文件路径 | 必填 |
| `--namespace` | 命名空间 | 自动选择 |
| `--extract-statistics` | 收集统计信息 | false |
| `--extract-relationships` | 提取关系 | true |
| `--import-schemas` | 迁移后导入 Schema | false |
| `--clear` | 导入前清除数据 | false |
| `--force` | 强制重新迁移 | false |
| `--llm-enum-extraction` | LLM 增强枚举提取 | false |

**完整迁移示例**:
```bash
python scripts/migrate_v0_to_v1.py \
  --config=conf/agent.yml \
  --namespace=test \
  --extract-statistics=true \
  --extract-relationships=true \
  --import-schemas \
  --llm-enum-extraction \
  --clear \
  --force
```

### 1.9 generate_business_config.py - 业务术语配置生成器

**功能**: 从数据架构设计文档和指标清单 Excel/CSV 生成业务术语配置文件 `business_terms.yml`，支持多行表头、表优先级过滤、文本清洗、业务术语质量过滤、LLM 增强、DDL 注释合并与最终术语精过滤。

**核心特性**:
- 支持 Excel (.xlsx) 和 CSV (.csv) 两种输入格式
- **表优先级过滤**: 优先使用 DIM/DWD/DWS 表，可选包含 ADS，排除 ODS
- **智能文本清洗**: 自动去除 emoji、序号标记、特殊符号，规范化空格
- **业务术语质量过滤**: 自动移除低质量术语（否定词开头、冗余描述、过长/过短术语）
- **无裸字段输出**: `term_to_schema` 仅保留带表名前缀的字段映射
- 智能处理多行表头（数据架构3行表头、指标清单2行表头）
- 自动检测工作表（优先 "Sheet1"，否则第一个）
- **LLM 增强**: 术语消歧、指标定义改写、冲突解决
- **批量 LLM 处理**: 减少 API 调用次数，提升执行效率
- **LLM 最终精过滤**: 对输出术语进行高质量筛选，剔除碎片词/泛化词/技术噪音
- 可合并现有 DDL 注释进行增强
- 生成三种映射关系：`term_to_table`、`term_to_schema`、`table_keywords`

**使用方式**:
```bash
python scripts/generate_business_config.py --config=conf/agent.yml --namespace=<name> [选项]
```

**核心参数**:
| 参数 | 说明 | 默认值 |

| `--arch-csv` | 数据架构详细设计 CSV 路径（兼容） | - |
| `--arch-sheet-name` | 数据架构工作表名称/索引 | 自动检测 |
| `--metrics-xlsx` | 指标清单 Excel 路径 | - |
| `--metrics-csv` | 指标清单 CSV 路径（兼容） | - |
| `--metrics-sheet-name` | 指标清单工作表名称/索引 | 自动检测 |
| `--output` | 输出 YAML 文件路径 | `conf/business_terms.yml` |
| `--merge-ddl` | 合并现有 DDL 注释 | false |
| `--max-table-priority` | 最大表优先级（DIM/DWD/DWS/ADS/ODS） | ADS |
| `--disable-text-cleaning` | 禁用 Excel 文本清洗 | false |
| `--disable-term-filter` | 禁用业务术语质量过滤 | false |

| `--strict-allow-pattern` | 严格过滤放行正则（可重复） | - |
| `--strict-keep-boolean` | 严格模式保留“是否”开头术语 | false |
| `--strict-keep-english` | 严格模式保留英文术语 | false |
| `--strict-keep-digits` | 严格模式保留含数字术语 | false |

**文本清洗功能**:

脚本自动对 Excel 单元格内容进行清洗，处理人类可读格式：
- **移除 emoji**: 🔥📊✅ 等
- **移除序号**: `1.`、`①`、`(1)`、`（一）` 等
- **规范化空格**: 多个空格/换行合并为单个
- **移除特殊符号**: `*#^~|\` 等

示例清洗效果:
| 原始文本 | 清洗后 |
|---------|--------|
| `1. 原始线索数\n这是详情` | `原始线索数 这是详情` |
| `① 首触线索数 (包含所有渠道)` | `首触线索数 (包含所有渠道)` |
| `✅ 有效线索数` | `有效线索数` |

使用 `--disable-text-cleaning` 可禁用此功能。

**表优先级过滤**:

脚本根据表名前缀自动过滤，优先级顺序:
| 优先级 | 前缀 | 说明 | 默认包含 |
|--------|------|------|----------|
| 1 | `dim_` | 维度表 | ✓ |
| 2 | `dwd_` | 明细事实表 | ✓ |
| 3 | `dws_` | 汇总事实表 | ✓ |
| 4 | `ads_` | 应用数据表 | ✓ |
| 5 | `ods_` | 操作数据表 | ✗ |

使用 `--max-table-priority=DWS` 可只包含 DIM/DWD/DWS 三层，排除 ADS/ODS。

**业务术语质量过滤** (v1.7+):

脚本自动过滤低质量业务术语，提升 text2sql 检索质量。过滤规则:

| 过滤类型 | 规则 | 示例 |
|----------|------|------|
| 长度检查 | 3-12 字符 | 过滤 "abc"（太短）、"这是一个非常长的术语名称"（太长） |
| 否定词开头 | 不/无/非/未 开头 | 过滤 "不包含大客户订单"、"未取消的订单数" |
| 冗余描述 | 包含 "的数量"、"的订单数" 等 | 过滤 "任务的数量"、"天的订单数量" |
| 词尾检查 | 不能以助词结尾 | 过滤 "有效线索的"、"试驾的" |

使用 `--disable-term-filter` 可禁用此功能（保留所有提取的术语）。

**严格术语过滤（text2sql 精度优先）**:

启用 `--strict-term-filter` 后，将进一步剔除以下高噪声术语：
- 过于泛化的单词（如“名称/时间/状态/版本”等）
- 以“是否”开头的布尔型术语（除非显式保留）
- 含英文/数字/符号/括号的术语（可用 `--strict-keep-*` 放行）
- 映射列数过多的术语（默认 >15 直接剔除）

可使用 `--strict-allowlist-file` 或 `--strict-allow-pattern` 保留关键业务词（如 VIN、NDA、PDS）。

**LLM 批量处理优化** (v1.7+):

启用 `--use-llm` 和 `--rewrite-with-llm` 时，支持批量处理减少 API 调用:
- `--llm-batch-size`: 每批处理的指标/字段数（默认 20）
- `--llm-rewrite-mode`: 处理模式
  - `batch`: 单次 LLM 调用处理多个定义（推荐，效率高）
  - `per-item`: 每个定义单独调用（慢，但兼容性更好）
- `--llm-no-cache`: 禁用响应缓存（相同输入不重复调用）

示例：批量大小 50 时，1000 个定义只需 20 次 API 调用 vs 1000 次。

**配置加载规则**:
生成后的 `business_terms.yml` 从 agent.yml 所在目录加载:
1. 如果 `./conf/agent.yml` 存在，则从 `./conf/business_terms.yml` 加载
2. 否则从 `~/.datus/conf/business_terms.yml` 加载

> 注意: 已移除环境变量 `BUSINESS_TERM_CONFIG` 支持，简化配置管理。

**故障排除**:

| 问题 | 解决方案 |
|------|----------|
| "0/5559 有效行" | 检查 `--arch-sheet-name` 是否正确，确认Excel表头行数 |
| 列名匹配失败 | 使用 `-vv` 查看实际列名，检查Excel格式 |
| 找不到工作表 | 使用 `pd.ExcelFile(xlsx).sheet_names` 查看可用工作表 |
| 内存不足 | 分批处理或使用 CSV 格式 |
| ODS 表过多（>50%） | 使用 `--max-table-priority=ADS` 或 `DWS` 过滤 |
| 术语包含乱码/emoji | 文本清洗自动处理，或使用 `--disable-text-cleaning` 禁用 |
| 低质量术语过多 | 启用 `--disable-term-filter=false`（默认启用）或使用 `--max-table-priority` 过滤 |
| LLM 调用次数过多 | 使用 `--llm-batch-size=50` 批量处理，或使用 `--llm-rewrite-mode=batch` |
| 输出文件过大（>500KB） | 结合使用 `--max-table-priority=DWS` + `--llm-final-filter` |

### 1.10 enrich_schema_from_design.py - Schema 元数据增强

**功能**: 从数据架构设计文档（Excel）直接增强 LanceDB 中的 Schema 元数据，支持数据层过滤和 LLM 智能匹配。

**与 generate_business_config.py 的区别**:
- `generate_business_config.py`: 生成业务术语配置文件（用于 text2sql 的术语映射）
- `enrich_schema_from_design.py`: 直接修改 LanceDB 中的 schema 元数据（提高元数据质量）

**核心特性**:
- **数据层过滤**: 支持 `--layers=dwd,dws,dim` 选择性处理特定数据层
- **智能匹配**: 精确匹配 + 模糊匹配 + LLM 语义匹配
- **匹配追踪**: 输出匹配来源统计（exact/fuzzy/none）
- **LLM 增强**: 智能匹配模糊表名、自动生成缺失注释

**核心增强内容**:
| 元数据字段 | 增强来源 | 说明 |
|------------|----------|------|
| `table_comment` | 逻辑实体业务含义 | 表的业务描述 |
| `column_comments` | 属性业务定义 + LLM生成 | 字段的详细业务含义 |
| `business_tags` | 主题域分组、分析对象 | 用于检索和分类 |
| `column_enums` | 字段名模式+安全分类 | 推断枚举值 |

**使用方式**:
```bash
python scripts/enrich_schema_from_design.py \
  --config=/root/.datus/conf/agent.yml \
  --namespace=test \
  --arch-xlsx=/path/to/数据架构详细设计v2.3.xlsx \
  --layers=dwd,dws,dim \
  [--dry-run | --apply]
```

**核心参数**:
| 参数 | 说明 | 默认值 |
|------|------|--------|
| `--config` | 配置文件路径 | 必填 |
| `--namespace` | 目标命名空间 | 必填 |
| `--arch-xlsx` | 数据架构设计 Excel 路径 | 必填 |
| `--arch-sheet-name` | 工作表名称/索引 | 自动检测 |
| `--layers` | 目标数据层（逗号分隔） | `dwd,dws,dim` |
| `--dry-run` | 预览变更，不实际修改 | - |
| `--apply` | 应用变更到 LanceDB | - |
| `--use-llm` | 启用 LLM 智能匹配和注释生成 | false |
| `--output` | 保存报告路径 | - |
| `-v, --verbose` | 详细输出 | false |

**设计文档格式要点**:
- Excel **第2行**是实际列名（header=1）
- **`逻辑实体（英文）`列实际存储物理表名**（如 `dwd_assign_dlr_clue_fact_di`）
- 表名匹配以 `逻辑实体（英文）` 列为优先

**使用示例**:

```bash

python scripts/enrich_schema_from_design.py \
  --config=/root/.datus/conf/agent.yml \

  --arch-xlsx=/path/to/数据架构详细设计v2.3.xlsx \
  --layers=dwd,dws,dim \
  --dry-run \
  --output=/tmp/enrichment_preview.txt

# 2. 应用增强 - 只处理 DWS 层
python scripts/enrich_schema_from_design.py \
  --config=/root/.datus/conf/agent.yml \
  --namespace=test \
  --arch-xlsx=/path/to/数据架构详细设计v2.3.xlsx \
  --layers=dws \
  --apply

# 3. LLM 增强模式（智能匹配和注释生成）
python scripts/enrich_schema_from_design.py \
  --config=/root/.datus/conf/agent.yml \
  --namespace=test \
  --arch-xlsx=/path/to/数据架构详细设计v2.3.xlsx \
  --layers=dwd,dws,dim \
  --apply \
  --use-llm

# 4. 验证增强效果
python scripts/check_migration_report.py \
  --config=/root/.datus/conf/agent.yml \
  --namespace=test
```

### 1.12 test_layer_priority.py - 层级优先级验证

**功能**: 验证 schema discovery 中的层级权重配置是否正确生效。模拟 `finalize_candidates()` 的权重应用逻辑，验证 DWS/DWD/DIM 层（白名单）获得加分，ODS 层（黑名单）被降权。

**层级优先级设计目标**:
| 优先级 | 前缀 | 层 | 权重策略 |
|--------|------|------|----------|
| 1 | `dws_` | 汇总层 | 白名单 (+0.05) |
| 2 | `dwd_` | 明细层 | 白名单 (+0.05) |
| 3 | `dim_` | 维度层 | 白名单 (+0.05) |
| 4 | `ads_` | 应用层 | 中性 (0) |
| 5 | `ods_` | 原始层 | 黑名单 (×0.7) |

**使用方式**:
```bash
# 1. 使用 Mock 数据测试（无需 LanceDB）
python scripts/test_layer_priority.py --mock --config=conf/agent.yml

# 2. 使用实际 LanceDB 数据测试
python scripts/test_layer_priority.py --lancedb --config=conf/agent.yml --namespace=test

# 3. 指定命名空间
python scripts/test_layer_priority.py --mock --config=/path/to/agent.yml --namespace=test

# 4. 输出结果到 JSON
python scripts/test_layer_priority.py --mock --config=conf/agent.yml --output=layer_test.json
```

**核心参数**:
| 参数 | 说明 | 默认值 |
|------|------|--------|
| `--config` | 配置文件路径 | 必填 |
| `--namespace` | 命名空间 | - |
| `--mock` | 使用 Mock 数据 | false |
| `--lancedb` | 使用 LanceDB 数据 | false |
| `--output` | 输出 JSON 文件 | - |

**与 check_search_text_fts.py 的区别**:

| 特性 | check_search_text_fts.py | test_layer_priority.py |
|------|--------------------------|------------------------|
| 用途 | FTS 搜索测试 | 层级权重验证 |
| 权重应用 | ❌ 绕过权重逻辑 | ✅ 完整应用权重 |
| 模拟真实流程 | ❌ 否 | ✅ 是 |
| 排名变化分析 | ❌ 无 | ✅ 有 |

**说明**: `check_search_text_fts.py` 直接调用 `storage.search_fts()`，该方法是纯 FTS 搜索，绕过了 `finalize_candidates()` 中的权重应用逻辑。因此 FTS 测试结果不代表真实 text2sql 行为。

## 五、故障排除

### 5.1 常见问题

| 问题 | 解决方案 |
|------|----------|
| **LanceError: Column definition does not exist** | **schema 缺少 `definition` 字段**。见下方详细处理步骤 |
| LLM 增强失败 | 禁用 LLM 增强模式，去掉 `--use-llm` 参数 |
| 模型下载超时 | 使用国内镜像：`bash scripts/download_models_cn.sh` |
| 权限错误 | 确保数据库用户有访问系统表权限 |
| 存储路径冲突 | 检查 `agent.yml` 中的 namespace 配置 |
| 迁移脚本查询失败 | 检查 `schema_metadata` 表是否包含 `definition` 和 `search_text` 字段 |

### 5.2 LanceDB Schema 错误处理

如果遇到 "Column definition does not exist" 错误，说明 schema 缺少必要字段。

**问题原因**：
- Schema 应同时包含 `definition`（原始 DDL）和 `search_text`（增强内容）两个字段
- 旧代码可能只创建了其中一个字段

**解决方案**：

```bash
# 1. 验证当前 schema 字段
python -c "
from datus.storage.schema_metadata.store_modules import SchemaStorage
from datus.storage.embedding_models import get_db_embedding_model

model = get_db_embedding_model()
storage = SchemaStorage(
    db_path='/root/.datus/data/datus_db_test',
    embedding_model=model
)
storage._ensure_table_ready()
print('Current schema fields:', sorted(storage.table.schema.names))

# 检查必要字段
required = ['definition', 'search_text', 'vector']
missing = [f for f in required if f not in storage.table.schema.names]
if missing:
    print(f'Missing required fields: {missing}')
else:
    print('✅ All required fields present')
"

# 2. 如果缺少字段，重建表
python -m datus.storage.schema_metadata.migrate_v0_to_v1 \
  --config=/root/.datus/conf/agent.yml \
  --namespace=test \
  --clear \
  --force \
  --import-schemas

# 3. 验证修复
python scripts/check_migration_report.py \
  --config=conf/agent.yml \
  --namespace=test
```

**预期结果**：
- Schema 应包含以下字段：`identifier`, `catalog_name`, `database_name`, `schema_name`, `table_name`, `table_type`, `definition`, `search_text`, `vector`, `table_comment`, `column_comments`, `column_enums`, `business_tags`, `row_count`, `sample_statistics`, `relationship_metadata`, `metadata_version`, `last_updated`

### 5.3 回滚操作

```bash
# 从备份恢复
bash scripts/backup_storage.sh  # 先创建新备份
rm -rf ~/.datus/data/datus_db
mv ~/.datus/data/datus_db.backup_* ~/.datus/data/datus_db
```
